# Генератор личных карточек учета выдачи СИЗ

Приложение на Python с графическим интерфейсом для формирования Excel-файлов личных карточек учета выдачи СИЗ.

Проект:

- читает `data/norms.xlsx` с нормами выдачи;
- в пакетном режиме читает `data/employees.xlsx` с работниками; в GUI данные работника вводятся в форму;
- ищет нормы по паре `Подразделение + Должность`;
- создает отдельную карточку Excel для каждого найденного работника;
- сохраняет результат в папку `output`;
- записывает ненайденные должности или подразделения в `output/warnings.xlsx`.

В проекте есть простой графический интерфейс на `tkinter`, а основная логика вынесена в функции, которые можно вызывать из кода.

## Важно про примерные данные

Демонстрационные файлы в `sample_data` предназначены для обучения и не являются рабочим источником норм приложения. `data/norms.xlsx` является внешним рабочим источником норм СИЗ.

Рабочие файлы лежат в папке `data`. Учебные файлы лежат отдельно в папке `sample_data`.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Подготовка демонстрационных файлов

В проект уже добавлены примерные файлы:

- `sample_data/norms_sample.xlsx`
- `sample_data/employees_sample.xlsx`

Если нужно создать их заново, выполните:

```bash
python create_sample_files.py
```

Эта команда создаёт или перезаписывает только два перечисленных файла в `sample_data`, не изменяет `data` и не создаёт `templates/card_template.xlsx`. Обязательный рабочий шаблон поставляется отдельно в составе проекта; этой командой нельзя восстановить весь рабочий набор файлов.

Создаваемый пример норм использует старые заголовки (`Норма выдачи`, `Срок носки`, `Основание`), которые не совпадают с обязательными колонками текущего генератора. Он не является готовой заменой рабочего файла; актуальная структура описана ниже.

## Рабочие данные

Папка `data` предназначена для реальных рабочих файлов:

- `data/norms.xlsx` — единственный внешний рабочий источник норм СИЗ;
- `data/employees.xlsx` — реальные данные работников для пакетной генерации.

Для генерации также обязателен шаблон `templates/card_template.xlsx`. GUI не требует `data/employees.xlsx`.

Папка `sample_data` нужна только для тестов и обучения. Файлы из нее не используются автоматически при запуске программы.

## Запуск

Пакетная генерация по файлам `data/norms.xlsx` и `data/employees.xlsx`:

```bash
python main.py
```

После запуска файлы появятся в папке `output`.

Графический интерфейс:

```bash
python app.py
```

На Windows интерфейс также можно запустить двойным кликом по файлу:

```bash
run_app.bat
```

GUI использует файл `data/norms.xlsx` для списков подразделений и должностей. Готовые карточки сохраняются в папку `output`.

## Заявка на добавление должности в нормы СИЗ

Если нужной должности нет в `data/norms.xlsx` или для выбранной пары `Подразделение + Должность` отсутствуют нормы, в GUI можно нажать кнопку `Заявка на добавление должности`. Заявка сохраняется как отдельный Excel-файл в папке `requests`.

Заявка не добавляет должность автоматически в нормы СИЗ и не изменяет `data/norms.xlsx`. Решение о добавлении принимает специалист по охране труда после проверки описания работ и основания для пересмотра норм.

ФИО работника и пол работника в заявке не запрашиваются, так как для пересмотра норм СИЗ они не требуются. В заявке указываются только ФИО и контакт инициатора, чтобы специалист по охране труда мог уточнить сведения.

После создания заявку можно сразу открыть из формы кнопкой `Открыть заявку`. Папку со всеми созданными заявками можно открыть кнопкой `Открыть папку заявок`.

Готовая карточка создается с двумя листами:

- `Лицевая сторона` — сведения о работнике, размеры и таблица положенных СИЗ;
- `Оборотная сторона` — таблица учета фактической выдачи и возврата СИЗ.

Шаблон `templates/card_template.xlsx` приведен к печатному виду файла `reference/Карточка СИЗ.xlsx` по Приказу Минтруда № 766н. Лист `Лицевая сторона` создан по листу `стр.1` образца, а лист `Оборотная сторона` создан по листу `стр.2`.

Оба листа настроены для печати в книжной ориентации и помещаются по ширине на одну страницу.

## Сборка portable EXE

Windows-версия собирается PyInstaller в режиме `onedir`. Python конечному
пользователю не требуется.

Установка зависимостей сборки:

```bash
python -m pip install -r requirements-dev.txt
```

Повторная сборка:

```text
build_exe.bat
```

Готовая переносимая папка создается по пути
`release/SIZCardGenerator`. В ней находятся `SIZCardGenerator.exe`, каталог
`_internal`, внешние `data/norms.xlsx` и `templates/card_template.xlsx`, а
также пустые рабочие каталоги `output/backups` и `requests`.

Приложение можно переносить целиком в любой доступный каталог. Оно определяет
рабочие пути от физического расположения `SIZCardGenerator.exe`, поэтому
обновление внешних норм или шаблона не требует пересборки EXE. Если один из
обязательных Excel-файлов отсутствует, программа показывает его полный путь и
не создает замену автоматически.

`release` является результатом сборки. Скрипт удаляет и пересоздаёт `build`, `dist` и `release/SIZCardGenerator`, включая файлы внутри существующего релиза. Перед пересборкой сохраните нужные карточки и заявки вне этих каталогов. Не храните постоянные пользовательские данные в разработческом `release`: для работы используйте отдельную копию всей папки `SIZCardGenerator`.

Для выпуска актуального portable-комплекта после изменения его компонентов выполните сборку и [проверку portable-релиза](docs/portable-verification.md). Microsoft Excel нужен для встроенного предварительного просмотра и печати, но не для базовой генерации XLSX.

В готовой карточке также есть поля для фактической выдачи СИЗ:

- `Дата выдачи`
- `Количество выдано`
- `Лично / карточка`
- `Подпись получившего СИЗ`
- `Дата возврата`
- `Количество возвращено`
- `Подпись сдавшего СИЗ`
- `Акт списания, дата и номер`

Эти поля добавляются в карточку, но автоматически не заполняются. Программа заполняет в нижней таблице только `Наименование СИЗ`, а данные фактической выдачи и возврата вносятся вручную.

## Функции генератора и демонстрационный запуск

Функции находятся в [generator.py](siz_card_generator/generator.py) и используются существующим GUI.

Получить список подразделений из `data/norms.xlsx`:

```python
from siz_card_generator.generator import get_departments

departments = get_departments("data/norms.xlsx")
```

Получить список должностей по выбранному подразделению:

```python
from siz_card_generator.generator import get_positions_by_department

positions = get_positions_by_department("data/norms.xlsx", "Склад")
```

Создать одну карточку без `employees.xlsx`:

```python
from siz_card_generator.generator import create_single_card

employee = {
    "Табельный номер": "GUI-001",
    "ФИО": "Тестов Тимофей Тимофеевич",
    "Подразделение": "Склад",
    "Должность": "Кладовщик",
    "Дата приема": "2024-02-01",
    "Пол": "Учебно: мужской",
    "Рост": "Учебно: 178",
    "Размер одежды": "Учебно: 50",
    "Размер обуви": "Учебно: 42",
    "Размер головного убора": "Учебно: 58",
    "Размер перчаток": "Учебно: 9",
}

create_single_card(
    employee=employee,
    norms_path="data/norms.xlsx",
    template_path="templates/card_template.xlsx",
    output_dir="output",
)
```

Такой же пример есть в файле [test_single_card.py](test_single_card.py). Это вспомогательный демонстрационный сценарий без автоматических assert-проверок, а не полноценный автоматизированный тест. Он читает рабочие нормы и записывает результат в `output`; карточка создастся только при наличии точной пары `Склад + Кладовщик`. Отсутствие этой пары не требует добавления норм для запуска примера.

## Структура входных файлов

### data/norms.xlsx

Обязательные колонки:

- `Подразделение`
- `Должность`
- `Наименование СИЗ`
- `Пункт Норм / основание`
- `Единица измерения, периодичность выдачи`

Также поддерживаются колонки:

- `Количество на период`
- `Примечание`

Значения в колонках `Количество на период` и `Примечание` могут быть пустыми.
Пустое количество переносится в карточку как пустая ячейка.

### data/employees.xlsx

Обязательные колонки:

- `Табельный номер`
- `ФИО`
- `Подразделение`
- `Должность`
- `Дата приема`
- `Пол`
- `Рост`
- `Размер одежды`
- `Размер обуви`
- `Размер головного убора`
- `Размер перчаток`

## Как работает поиск норм

Генератор сравнивает подразделение и должность после `strip().lower()`: игнорируется регистр, пробелы удаляются только по краям строки. Внутренние пробелы автоматически не нормализуются.

В GUI подсказки фильтруются по введённой подстроке, но для создания карточки требуется полное значение из списка. Проверка выбранных значений GUI учитывает регистр и удаляет пробелы по краям; фильтрация подсказок не назначает нормы по сходству.

Например, работник из `data/employees.xlsx` получит нормы только если в `data/norms.xlsx` есть строка с тем же подразделением и той же должностью.

Если совпадение не найдено при пакетном запуске или вызове `create_single_card`, карточка для такого работника не создаётся, а запись попадает в `output/warnings.xlsx`. GUI может отклонить введённую пару раньше, при проверке значений списков, и показать сообщение без создания отчёта.

Программа формирует карточки только по утвержденным нормам из `data/norms.xlsx`.
Она не назначает СИЗ самостоятельно и не дополняет отсутствующие нормы.
