# Правила проекта генератора карточек СИЗ

## Единственный источник норм

Файл `data/norms.xlsx` является единственным источником сведений о положенных СИЗ.

Запрещено использовать для определения положенных СИЗ:

- штатное расписание;
- перечни должностей;
- кадровые выгрузки;
- файл `positions.xlsx`;
- прежний скрипт `check_positions.py`;
- автоматически рассчитанные или предполагаемые соответствия должностей.

## Правило определения СИЗ

Если пара `Подразделение + Должность` присутствует в `data/norms.xlsx`, программа использует только перечисленные для неё СИЗ.

Если пары нет в `data/norms.xlsx`, карточка не создаётся и СИЗ не назначаются.

Отсутствие должности в нормах не является ошибкой данных. Это означает, что в действующих утверждённых нормах для неё не предусмотрены СИЗ.

## Точное сопоставление

Разрешено точное сопоставление пары `Подразделение + Должность` с технической нормализацией, уже реализованной в коде. В генераторе это `strip().lower()`: регистр игнорируется, пробелы удаляются только по краям, внутренние пробелы не нормализуются.

Для определения норм запрещены fuzzy matching, подбор похожей должности, substring matching, автоматическая замена одной должности другой, перенос СИЗ между похожими должностями и назначение СИЗ по аналогии. Существующая фильтрация подсказок GUI по подстроке не является сопоставлением для назначения норм и не отменяет проверку точной пары.

## Перед изменением

- Прочитать относящийся к задаче код и проверить `git status` и текущую ветку. Не затрагивать посторонние изменения.
- Не изменять `data/norms.xlsx` без прямого указания пользователя. При разрешённом изменении сначала создать резервную копию, проверить структуру и вычислить исходный SHA-256.
- Перед разрешённым изменением `templates/card_template.xlsx` зафиксировать исходный SHA-256 и параметры, которые должны сохраниться.

## Во время изменения

- Не вводить штатное расписание, `positions.xlsx`, сравнение со штаткой, похожие должности или альтернативные источники норм без отдельного прямого задания пользователя.
- Изменять шаблон только в пределах задачи. Сохранять содержимое остальных ячеек, размеры строк и колонок, объединения, области печати, шрифты, оформление, печатные параметры и структуру листов, если их изменение не является целью задачи.
- Не менять алгоритм сопоставления при редактировании документации.

## Проверка результата

- Выбирать проверки по затронутому поведению; для изменений только документации достаточно сверки с кодом, проверки ссылок и `git diff --check`.
- После разрешённого изменения норм вычислить SHA-256 повторно, проверить структуру и создание карточек для существующей пары, а также отказ для отсутствующей пары.
- После изменения шаблона вычислить SHA-256 повторно, проверить сохранение незатронутых параметров, создать тестовую карточку и проверить печать по процедуре ниже.
- Если задача не предусматривает изменение норм или шаблона, эти файлы должны остаться неизменными.

## Git и фиксация изменений

Не создавать git commit и не выполнять git push без явного указания пользователя.

Если пользователь разрешил фиксацию изменений и изменялся `data/norms.xlsx`, изменение норм следует оформлять отдельным логически самостоятельным коммитом.

## Заявки

Заявка на добавление должности:

- сохраняется отдельно в папке `requests`;
- не изменяет нормы автоматически;
- не является основанием для автоматического назначения СИЗ.

## Запрещённые действия

Не допускается:

- самостоятельно подбирать СИЗ;
- переносить СИЗ с похожей должности;
- назначать нормы по сходству названия, разряду или категории;
- создавать нормы по штатному расписанию;
- восстанавливать удалённую логику сравнения со штаткой;
- создавать отчёты `positions_check.xlsx`.

## Проверка программы

Основные проверки:

- запуск: `python app.py`;
- запуск через `run_app.bat`;
- загрузка подразделений и должностей только из `data/norms.xlsx`;
- создание карточки для существующей пары;
- отказ в создании карточки для отсутствующей пары;
- неизменность `data/norms.xlsx` после работы программы.

## Portable-релиз

Если пользователь поставил задачу получить актуальный portable-релиз, после успешной проверки исходников пересобрать его при изменении кода приложения, `data/norms.xlsx`, `templates/card_template.xlsx`, `app_icon.ico`, `version_info.txt`, `SIZCardGenerator.spec` или build-файлов. Изменение одной документации само по себе пересборки не требует.

Подробная процедура: [проверка portable-релиза](docs/portable-verification.md).
